# Multi-Browser Editions — Firefox / Chrome / Edge

Status: implemented 2026-07-17. See ADR-0008 for the layout decision.

## Layout

| Path | Checked in | Generated by sync |
|---|---|---|
| `apps/shared/src`, `apps/shared/assets` | yes | — |
| `src/` (core, adapters) | yes | — |
| `apps/<edition>/manifest.json`, `README.md` | yes | — |
| `apps/<edition>/src`, `assets`, `lib` | no (gitignored) | `scripts/sync-extension-lib.sh` |

One source tree, three loadable extension dirs. `sync-extension-lib.sh` copies
`src/` → each edition's `lib/` and `apps/shared/{src,assets}` → each edition.
Only `manifest.json` differs per edition.

## Browser differences handled

- **API namespace** — Firefox exposes `browser` (promises); Chrome/Edge expose
  `chrome` (promises since MV3). Shared entry points alias once:
  `const browser = globalThis.browser ?? globalThis.chrome;` — no polyfill dependency.
- **Manifest** — Firefox keeps `browser_specific_settings.gecko`; Chrome/Edge
  manifests drop it and add `minimum_chrome_version`. Versions must match across
  all three (enforced by `scripts/check.sh`).
- **Module loading** — content script uses dynamic `import()` of
  `runtime.getURL('lib/...')` URLs; works in both engines because the imported
  paths are listed in `web_accessible_resources`.

## Build & verify

```bash
bash scripts/package-extension.sh firefox-extension   # dist/videodefaults-<v>.zip
bash scripts/package-extension.sh chrome-extension    # dist/videodefaults-chrome-<v>.zip
bash scripts/package-extension.sh edge-extension      # dist/videodefaults-edge-<v>.zip

DISPLAY=:0 node scripts/test-chrome-smoke.mjs   # loads chrome edition in Chromium,
                                                # stubs youtube.com/watch, asserts 2x applied
DISPLAY=:0 node scripts/test-extension-e2e.mjs  # Firefox E2E via web-ext + RDP
```

CI packages all three editions on every dev push; the release workflow signs
the Firefox zip with AMO. Chrome Web Store / Edge Add-ons publishing is not
wired up (no store credentials yet — see `docs/ai/questions-for-K.md` Q3).

## Edge specifics

Edge is Chromium: the edition is byte-identical to Chrome today. It exists as a
separate dir so an Edge-specific manifest divergence (store ids, Edge-only
fields) never forks shared code.
