# Contributing

## Setup

```bash
npm install
bash scripts/test.sh
bash scripts/check.sh
```

Both must pass before opening a PR.

## Branch model

- `dev` — active development, target your PRs here.
- `main` — release only, linear history, no merge commits.

## Code style

- Plain JS + JSDoc in `src/` and `apps/` — no TypeScript, no runtime dependencies shipped in the extension.
- No comments unless the *why* is non-obvious (a subtle invariant, a workaround, something that would surprise a reader).
- Shared logic lives in `src/` and `apps/shared/`; per-edition dirs (`apps/{firefox,chrome,edge}-extension`) hold only `manifest.json` and `README.md` — everything else is generated by `scripts/sync-extension-lib.sh`, don't edit it directly.

## Commits

Conventional commits: `type(scope): description`, types `feat fix docs test refactor chore ci build perf`. Keep commits atomic — one logical change per commit, only the files it actually touches.

## Keyboard shortcuts

If you add or change a shortcut:

1. Make it configurable via `src/core/shortcuts.config.json`.
2. Update `docs/keyboard-quickstart.md` in the same commit.
3. Open a GitHub issue if the change needs porting to an edition the shared source tree doesn't already cover.

## Tests

Unit tests run via Node's built-in test runner (`node --test tests/unit/*.test.js`, no test framework dependency). Add or update tests for any behavior change in `src/`.
