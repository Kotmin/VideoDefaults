# Commit Conventions

## Format

```
type(scope): description
```

`scope` is optional. `!` after scope signals a breaking change.

### Allowed Types

| Type | When to use |
|------|-------------|
| `feat` | New user-facing feature |
| `fix` | Bug fix |
| `docs` | Documentation only |
| `test` | Tests only, no behavior change |
| `refactor` | Internal restructure, no behavior change |
| `chore` | Build, tooling, config — not shipped behavior |
| `ci` | CI/CD workflow changes |
| `build` | Changes to the build/package process |
| `perf` | Performance improvement |

### Examples

```
feat(core): add playback speed validation
fix(youtube): preserve manual rate changes per video
test(settings): add migration tests for v1 schema
chore(scripts): update package-firefox.sh wrapper
ci(dev): upload unsigned artifact on push to dev
docs(decisions): record module resolution strategy
```

### Forbidden

Commit messages must not mention AI assistant or tool names:
`claude`, `chatgpt`, `gpt-4`, `copilot`, `gemini`, `openai`, `anthropic`, `cursor`, `codeium`, `tabnine`, `generated by`, `ai-generated`.

## Atomic Commit Rules

One logical change per commit. A commit should:

- Do exactly one thing (one bug fixed, one feature added, one doc updated)
- Leave the test suite passing
- Not mix behavior changes with doc/formatting changes unless inseparable
- Include the related tests when behavior changes (red → green in same logical pair)

### Anti-patterns to avoid

- Mixing a refactor with a feature in one commit
- "WIP" commits pushed to `dev`
- Bulk "fix all the things" commits
- Committing generated files that belong in `.gitignore`

## Validation

The validator lives at `tools/commit-check/validate_commit_message.py`.

Install the local hooks (once per clone):

```bash
bash scripts/install-git-hooks.sh
```

This installs `commit-msg` (validates each new commit) and `pre-push` (validates the full push range before sending to remote).
